# Otto Control 审计取证与证据交接规程

## 1. 适用场景

安全事件、越权调查、计费争议、监管检查或诉讼保全。一般运维排障不得借用取证权限批量导出客户数据。

## 2. 发起与批准

1. 发起人说明客户、案件编号、目的、范围和接收方。
2. 具有 `forensic_export.create` 权限的管理员创建审批。
3. 另一名启用 MFA 的管理员批准；发起人不能批准自己的申请。
4. 存在法律保全时按保全范围处理，禁止扩大到无关数据。

## 3. 生成

接口：`POST /v1/admin/data-governance/forensic-exports`。

产物包括：

- 请求 ID、客户 ID、生成时间和驻留区域；
- 客户控制面白名单快照的 SHA-256，不直接嵌入客户业务正文；
- 审计链验证结果、头哈希、序号范围和 Ed25519 签名；
- 外部锚/WORM 的状态通过现有审计接口独立核验；
- 最小交接链条和已知限制。

## 4. 交接

交付前复核范围和脱敏结果。记录交付人、接收人、时间、介质、清单哈希、签名键 ID 和用途。接收方应在隔离环境核验 SHA-256、签名和审计链，不得通过聊天工具明文发送证据包。

## 5. 法律保全

- 创建：`POST /v1/admin/data-governance/legal-holds`
- 解除：`POST /v1/admin/data-governance/legal-holds/:id/release`

创建与解除都要求双人审批。有效保全会在注销事务内再次检查并阻止删除。保全必须有范围、理由和可选到期时间，不允许无范围、无期限地冻结所有客户数据。

## 6. 验证与关闭

案件结束后核验所有副本是否按授权返还或销毁，解除不再需要的法律保全，并记录结案意见。对外提供前由法律顾问确认权限、程序和最小必要范围。

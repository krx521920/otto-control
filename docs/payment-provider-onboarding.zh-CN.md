# Otto 支付、充值与发票接入边界

Otto Control 已提供企业与组织隔离的支付订单、幂等创建、回调前绑定校验、
积分入账/冲正动作、失败重试和死信状态。当前内置的 HMAC-SHA256 Provider
只适用于自建或测试支付服务，**不是微信支付或支付宝正式协议实现**。

在商户专用适配器、生产密钥和真实小额交易验收完成前，扫码充值与自动开票必须保持关闭。

## 已完成的通用内核

- 订单绑定 `customerId + organizationId`，积分不会写入其他企业账本。
- 同一个幂等键不能用不同金额、币种、企业或积分数量重放。
- 回调验签后，先核对供应商、商户订单、币种和金额，再允许持久化。
- 重复回调不重复入账；账本失败进入指数退避，达到上限进入死信。
- 密钥、支付正文和付款人信息不进入普通审计日志。
- 发票定义了供应商接口契约，但还没有连接正式税务或第三方开票服务。

## 微信支付 API v3 仍需外部准备

1. 以实际收款主体申请并审核通过微信支付商户号，确定直连商户或服务商模式。
2. 准备商户号、应用 AppID、商户 API 证书序列号、商户 API 私钥。
3. 在商户平台设置并安全保管 32 字符 APIv3 密钥。
4. 配置微信支付公钥或平台证书及轮换流程，用于响应和回调验签。
5. 准备公网 HTTPS `notify_url`，完成签名验证、AES-256-GCM 回调解密、
   金额/商户号/订单号核对和重复通知测试。
6. 提供退款、关单、日账单下载和资金对账权限。
7. 将证书私钥和 APIv3 密钥放入 KMS/HSM 或受控 Secret，不进入仓库和普通构建机。

正式适配器必须实现微信支付 API v3 的 SHA256-RSA 签名与回调解密，
不能复用当前通用 HMAC Provider。

## 支付宝仍需外部准备

1. 以实际收款主体在支付宝开放平台创建并审核应用，取得 AppID 和产品权限。
2. 生成并托管应用 RSA2 私钥，配置应用公钥/证书及支付宝公钥/证书。
3. 配置正式网关、签名算法、字符集、同步返回地址和公网 HTTPS 异步通知地址。
4. 对异步通知执行 RSA2 验签，并核对 AppID、商户订单、金额、币种和交易状态。
5. 开通退款、查询、账单下载能力，完成重复通知、乱序通知和退款对账测试。
6. 私钥和证书必须进入受控密钥系统，不能由桌面客户端持有。

## 发票仍需外部准备

1. 确认开票主体、纳税人识别号、税务登记、商品和服务税收分类编码及税率。
2. 选择税务数字账户人工开票，或签约具备接口能力的合规开票服务商。
3. 获取服务商生产账号、接口凭据、额度、回调和红冲能力。
4. 明确发票抬头、税号、邮箱等个人/企业信息的保存期限、访问权限和删除规则。
5. 完成支付、退款、红冲、发票状态和财务账单的一致性验收。

## 正式启用门禁

以下任一项缺失时，Control 只能显示“支付渠道待开通”，不能允许真实充值：

- 商户主体审核和生产权限；
- 专用 Provider 适配器与官方协议契约测试；
- KMS/HSM 或同等级密钥托管；
- 公网 HTTPS 回调及来源验签；
- 真实小额支付、退款、重复回调和日账单对账证据；
- 财务确认的积分兑换规则、退款规则和发票规则。

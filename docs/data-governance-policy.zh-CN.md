# Otto Control 数据治理与保留制度

版本：2026-08-01  
适用范围：Otto 商业控制面，不包含客户私有 Otto Server 内的聊天正文、附件、会议内容和企业知识原文。

> 本文件是产品与运维制度模板，不构成法律意见。正式商用前，经营主体、隐私联系人、期限、适用地区、财税义务和数据出境安排必须由法律顾问及客户的数据保护/安全负责人复核。

## 1. 治理原则

1. 目的明确、最小必要，不把“以后也许有用”作为长期保存理由。
2. 默认在合同约定的中国境内区域处理；区域首次绑定后不得通过改环境变量静默迁移。
3. 控制面默认只接收授权、计费、运行健康和安全审计数据，不接收聊天、文件、会议或提示词正文。
4. 数据导出采用字段白名单；密码、令牌、MFA 秘钥、签名私钥、凭据和密文字段不得进入导出。
5. 注销采用“申请、冷静期、双人审批、法律保全复核、执行、签名结果”流程。
6. 法律要求尚未届满或技术上无法立即删除的数据停止其他处理，只允许受控存储、安全保护、法定义务和争议处理。
7. 审计事件只记录最小操作事实，不记录用户正文；哈希链和 WORM 证据不得以“删除”为名静默改写。

## 2. 数据分类与默认处置

| 数据类 | 主要内容 | 默认位置 | 注销处置 |
|---|---|---|---|
| 客户身份 | 客户 ID、企业名称、区域 | `control_customers` | 名称去标识化，稳定客户 ID 仅用于账务和审计关联 |
| 部署身份 | 部署、组织、机器指纹、授权 | `control_deployments`、`control_licenses` | 组织与机器指纹去标识化，授权撤销，令牌版本递增 |
| 健康遥测 | 版本、粗粒度资源、错误码、成功率、耗时 | `control_telemetry_events` | 注销时删除；日常默认保留 90 天 |
| 临时安全状态 | Nonce、更新分配、实时席位 | 多个临时状态表 | 注销时删除；过期后自动清理 |
| 计费账本 | 企业积分、金额、模块、时间 | `control_enterprise_credit_accounts`、`control_credit_*` | 企业余额按客户与组织双重隔离；注销后去除组织、部署、描述和自定义元数据，限制处理并按配置期限保留 |
| 安全审计 | 操作者、动作、目标、哈希链、锚、WORM 回执 | 审计表与独立对象存储 | 限制处理，按配置期限到期处置，不改写既有证据链 |
| 导出记录 | 请求人、理由、清单哈希、交付结果 | `control_data_governance_requests` | 交付内容摘要默认 30 天后限制，只保留最小请求与哈希证据 |

默认期限是工程基线，不是所有客户和行业的统一法定期限。电子商务交易记录等特殊数据可能存在更长法定保存义务，应由合同和法律清单覆盖。

## 3. 客户注销流程

1. 具有 `customer_erasure.manage` 权限的管理员创建注销请求并说明原因。
2. 系统进入默认 14 天冷静期；期间可先完成客户数据导出。
3. 执行前由另一名管理员通过 MFA 会话批准 `customer_erasure.execute`。
4. 执行事务内再次检查：请求仍待处理、冷静期已结束、没有有效法律保全、没有未结算冻结积分。
5. 系统逐类执行删除、匿名化或限制处理，立即撤销授权，并生成带 SHA-256 和 Ed25519 签名的结果。
6. 备份中的历史副本不在线恢复使用，在正常保留周期内自然淘汰；灾难恢复若恢复到注销前时间点，必须重放注销清单。

所有客户导出、注销和取证请求都必须记录 `dueAt`。默认产品目标为 15 个自然日；注销冷静期晚于该日期时，截止时间自动顺延到允许执行日。查询结果必须显示 SLA 状态、完成时间和 manifest SHA-256，不得仅以工单评论或人工口头确认作为完成证据。

## 4. 数据导出

- 路径：`POST /v1/admin/customers/:customerId/data-exports`。
- 导出为即时签名 JSON，包含策略版本、驻留区域、数据快照、SHA-256 和签名键 ID。
- 导出不包含服务器秘钥、密码哈希、令牌、MFA 材料、License 签名值和遥测正文载荷。
- 每次导出写入防篡改审计链；调用方负责在受控位置保存并登记接收人。

## 5. 数据驻留与跨境

- `CONTROL_DATA_REGION` 在数据库首次初始化时持久绑定，后续配置漂移会阻止服务启动。
- `CONTROL_ALLOWED_DATA_REGIONS` 必须包含主区域。
- 跨境默认关闭。开启时必须同时配置多个允许区域及 `CONTROL_CROSS_BORDER_ASSESSMENT_ID`。
- 配置项只是一道技术门禁，不代替告知、单独同意、个人信息保护影响评估、安全评估、标准合同或认证等适用程序。

## 6. 个人信息权利与审计

应提供查阅、复制、转移、更正、删除/匿名化、限制处理、注销、撤回同意和解释说明的便利入口，并记录申请、处理意见、拒绝理由和完成结果。正式运营主体应定期开展合规审计并留存整改证据。
